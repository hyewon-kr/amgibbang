## 실제 요청

`loadKnowledge`는 규칙·인덱스·여섯 전문을 서버에서 캐싱한다. `storyInstructions`는 선택 장르의 전문만 구분자로 감싸 실제 `instructions` 문자열에 삽입한다. 아이돌은 두 작품 모두 포함한다. 다른 장르·예전 요약·발췌·topic 점수는 전달하지 않는다. 인덱스는 원문 파일을 가리키는 메타데이터이며 모델에 전달되는 전문을 대신하지 않는다.

## 문단과 검증

각 `paragraphs` 항목은 하나의 자연스러운 문단이다. 화자 교체는 새 항목, 중요 반응은 짧은 항목으로 쓰되 모든 문장을 기계적으로 분리하지 않도록 지시했다. 기존 조립기는 항목 사이에 `\n\n`을 넣고 Reader는 각 문단을 별도 `<p>`로 렌더링한다. `white-space: pre-line`은 문단 내부 줄바꿈을 유지하므로 CSS 변경은 필요하지 않았다. JSON 왕복·문단 개수·주석 트리거·줄바꿈 CSS를 테스트했다.

전문 보존, 다섯 장르별 전체 포함/다른 장르 제외, 실제 SDK 요청에서 아이돌 전문 둘 모두 포함, 기존 스키마·주석·Flow Summary와 호출 횟수를 검증한다. 모델 `gpt-6-luna`, reasoning `none`, 출력 토큰 한도와 API 계약은 변경하지 않았다. 배포는 이번 작업에서 하지 않는다.
