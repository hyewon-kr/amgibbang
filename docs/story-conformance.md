# Storytelling 규칙 준수 검증

이번 작업은 검증 체계 구현이다. 모델 gpt-6-luna / reasoning none, 공개 출력 스키마와 Reader/Flow Summary를 변경하지 않는다. AI 검수 호출·의미 실패 자동 재생성·신규 배포는 없다.

## 현재 전달 상태

공개 버전은 이전 이름 규칙 작업에서 push된 9649763이며 Firebase build-2026-10-14-001 rollout이 성공했다. 이번 검증 체계가 배포됐다는 뜻은 아니다. 배포된 코드의 `storyInstructions`로 최종 instructions를 재구성할 수 있다. 실제 API는 그 문자열을 instructions에 전달하며 선택 장르의 원문 전체만 포함한다(아이돌은 둘). 공통/선택 장르 규칙과 개념명 우선·역할 호칭 전용 이름 지시가 들어간다. Golden 안의 개인 이름은 원문 보존 때문에 존재하지만 최신 명명 지시가 명시적으로 이를 우선한다.

운영 로그에 과거 요청의 전체 instructions나 사용자 원문은 없으므로 특정 과거 결과의 정확한 요청 전문을 서버 로그에서 복원할 수는 없다. 로컬 구현에 instructions SHA-256과 effort 로그를 추가하여 앞으로 기록과 생성 요청을 비교할 수 있다. 키나 프롬프트 원문을 운영 로그에 기록하지 않는다. `auditRequest`는 전문 포함·다른 장르 제외·장르 규칙·명명 규칙과 원문 해시를 확인한다. SDK를 가로채는 기존 테스트에서도 실제 전송 instructions에 아이돌 전문 둘과 명명 지시가 있음을 확인한다.

## 판정

- 자동 검사: 스키마/필수 필드, ID/참조, 장르 메타데이터, 확인된 Fact Anchors/Steps의 동일성, 모든 사실의 passage 주석 연결, 정확한 주석 위치, 지정된 주요 개념명의 본문 존재.
- 의미 검사: 개념명의 인물이 실제 기능으로 사건에 기여하는지, 임의 이름 대체/불필요한 인간 중심인지, 본문의 과학적 정확성·인과·수량, 장르 유지, 원문 복제 여부.
- 좀비: 실제 좀비/좀비화된 존재의 사건 등장, 실질적 위협, 생존/방어/탈출/감염 갈등을 각각 별도 규칙으로 판단한다. 단어만으로 통과하지 않는다.
- 로판: 판타지와 의미 있는 관계 선택/변화. 아이돌: 공연/제작/컴백/팬 교류 등 업계 사건의 중심성. 미스터리: 실제 수사 및 개념·단서 기반 해결. 아카데미: 마법 작용이 일상/모험/관계의 결과를 변경.

자동 항목이 전부 통과해도 `pending_review`다. 명시적인 수동 fail이 있으면 `failed`, 모든 의미 항목에 pass와 실제 근거가 있어야 `passed`다. 자동 fail은 `automatic_failed`다. CLI 종료 코드는 0=전체 검토 통과, 1=실패, 2=의미 검토 대기이며 대기를 성공으로 간주하지 않는다. 인용은 지정 챕터 본문에 실제 포함되어야 하며 빈 근거·알 수 없는 규칙·중복 판정·허위 인용은 거부한다. 판정 이유의 타당성 자체는 사람이 책임진다.

**공개 서비스에는 아직 의미 검토 차단을 연결하지 않았다.** 기존 API 성공은 생성/구조 검증 성공이며 의미 품질 보증이 아니다. 출력 계약을 유지하기 위해 이번 판정은 별도 평가 리포트로 제공한다. 해당 제한을 숨기지 않는다.

## 재현

검토용 고정 분석을 재사용하는 네 사례를 마련했다: ECG와 전도 이상(RBBB/일부 AV block), 선천/적응면역, 경쟁적/순수 비경쟁적 저해, 세포호흡/ATP. ECG 사례는 모든 AF/VT 등 리듬을 포괄하는 검증이라고 주장하지 않는다. 같은 입력·장르·개인화·규칙/원문 해시를 기록한다. 생성의 확률적 차이는 반복 비교 대상으로 남는다.

저장된 실제 결과 평가(추가 API 호출 없음):

```sh
node --import tsx scripts/story-conformance.ts --case immunity --saved artifacts/immunity-idol-test.json
```

사람의 판정 JSON을 추가:

```sh
node --import tsx scripts/story-conformance.ts --case immunity --saved artifacts/immunity-idol-test.json --review path/to/review.json
```

판정 배열의 한 항목 예시(인용은 실제 본문이어야 함):

```json
{"ruleId":"idol.activity","status":"fail","reason":"본문 전체에서 공연 대신 침입자 제거가 중심이다.","evidence":[{"chapterId":1,"quote":"대식세포는 침입자를 감싸 삼키며 연습실 한쪽을 정리했다."}]}
```

실제 생성은 별도 명시적 옵션이며 유료다. 이번 작업에서는 실행하지 않았다.

```sh
OPENAI_MODEL=gpt-6-luna node --env-file=.env.local --import tsx scripts/story-conformance.ts --case immunity --generate --runs 2
```

한 실행 최대 세 반복이며 각 반복은 사용자가 명시한 테스트다. 실패했다고 의미 재생성하지 않는다. 기존 provider의 형식/주석 오류 복구 시도(최대 1회)는 그대로이며 발생하면 calls/응답별 토큰에 기록한다. 새 자동 재생성을 구현한 것은 아니다.

리포트: 모델/effort, 규칙 revision와 해시, Golden 버전/원문 해시, 최종 instructions와 해시, 입력/장르, 결과, 시간, 각 응답의 input/output/reasoning/cached 토큰, 자동 검사, 의미 상태, 위반 규칙·본문 근거. 저장된 과거 파일에 모델·버전·토큰이 없으면 unknown/null로 남기며 현재 버전을 소급 적용하지 않는다. `currentRequestAudit`는 현재 코드로 재구성한 요청이지 과거 요청의 캡처가 아니다.

리포트에는 검토용 입력과 결과가 포함되므로 로컬 `artifacts/conformance/`에 저장하고 Git에서 제외한다. 콘솔에는 판정·규칙 ID만 출력한다. 실제 사용자 개인정보를 테스트 자료로 사용하지 않는다.

## 확인한 실제 위반과 한계

저장된 실제 면역 아이돌 결과는 자동 검사 전부 통과했으나 `idol.activity`에 fail을 기록했다. “호중구는 무대 입구로 가장 먼저 달려가 침입자 앞을 막아섰다.”, “대식세포는 침입자를 감싸 삼키며 연습실 한쪽을 정리했다.” 등 행동이 면역 방어에 집중되고 아이돌 업무는 사건의 중심이 아니었다. 기존 파일의 생성 메타데이터가 부족하므로 최신 이름 규칙 배포에 대한 위반이라고 주장하지 않는다.

사용자가 제보한 민서/도영과 좀비 없는 결과는 중요한 검증 대상이지만 그 결과 전문·생성 버전이 현재 저장되어 있지 않다. 이번에 최신 공개 버전에서 재현했다고 말하지 않는다. 합성 좀비 키워드 부정 테스트는 실제 실패 사례와 구분한다.

최소 후속안: 요청 해시/규칙 revision를 일관되게 남기기, 인물과 기능·장르 사건의 의미를 동일 고정 사례로 반복 검토하기, 실제 확인된 실패 유형에 한정해 지시를 조정하기. 이름 블랙리스트나 좀비 단어 횟수로 전체 의미 준수를 보증하지 않는다. 외부 검수 AI 없이 신뢰할 수 있는 의미 판정에는 사람이 필요하다.
