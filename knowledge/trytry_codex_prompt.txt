[CODEX IMPLEMENTATION PROMPT — TRYTRY STORY GENERATION]

프로젝트명은 trytry다. 기존 암기빵/Amgippang이라는 이름을 새 기능 문구에 사용하지 말 것.

목표: 현재 저장소의 Storytelling 생성 파이프라인을 조사하고, 동봉된 trytry_golden_examples.txt 및 아래 규칙을 기준으로 스토리 생성 품질을 개선하라. 먼저 실제 저장소 구조·기존 프롬프트·스키마·테스트를 확인하라. 존재하지 않는 파일이나 인터페이스를 가정하지 말 것.

중요: golden_examples.txt는 '전체 원문 모음'이 아니라 채택된 이야기의 확인 가능한 발췌·줄거리·선호 장면을 정리한 참조본이다. 원문 전체가 없다고 해서 누락된 부분을 원문인 척 채우지 말 것. 판타지 아카데미 작품은 후보로 분류할 것.

1) 공통 생성 원칙
- Semantic Fidelity + Narrative Freedom: 원자료의 핵심 사실, 정의, 기전, 인과, 중요한 순서와 구별은 보존한다. 세계관·사건·대화·캐릭터 관계는 자유롭게 창작한다.
- Concept as Character + Function as Action: 개념을 의인화할 때 실제 학습 용어를 인물의 정체성/이름으로 우선 사용한다(예: 효소 경, 기질 양, 보조 T세포, 재상 안지오텐신 II, 포도당). 실제 기능이 그 인물의 행동·능력·직업·관계·갈등을 결정해야 한다. 모든 용어를 무조건 의인화하지 말 것.
- Concept-Driven Plot: 사건의 원인, 장애물, 선택, 발견, 해결이 실제 학습 개념의 작동 방식에서 나오도록 한다. 교과서 설명을 대사로 옮기는 데 그치지 말 것.
- Concept-Driven Discovery: 개념의 특징이 결정적 발견·반전·선택으로 이어질 때 자연스럽게 활용한다. 모든 개념마다 강제하지 않는다.
- Contextual Meaning: P/QRS/T처럼 생소한 기호·용어는 첫 등장이나 중요한 장면에서 짧은 한 문장 또는 행동 결과로 의미를 알려준다. 반복 설명은 피한다.
- In-World Notes: 수첩, 사건 기록, 실험 결과, 전광판, 제작 메모 등 세계 안의 매체를 이용해 '기질 농도 증가 — 저해 효과 감소'처럼 짧고 정확하게 정리할 수 있다. 과용하지 않는다.
- Conceptual Closure: 가능하면 마지막 장면/대사에서 핵심 개념을 회수하면서 소설다운 여운을 남긴다. 교과서 요약으로 소설을 끝내지 않는다.
- 장르에 맞는 실제 사건과 대화가 중심이다. 유머는 선택 사항이다. 설명 과잉, 경직된 반복 플롯, 불필요한 인명, 부자연스러운 대사를 피한다.
- 학습 개념을 인물화하지 않는 편이 나은 경우에는 증거, 마법 규칙, 환경, 물건, 갈등 구조 등으로 표현해도 된다.
- 스토리 본문은 소설답게, 주석은 정확한 정의·비유 한계, Flow Summary는 원자료의 구조와 인과관계를 명확히 보여주도록 분리한다.

2) 장르별 규칙
A. 로맨스판타지: 제국·궁정·마법·정치·위기와 절제된 로맨스. 로맨스가 학습 기전과 자연스럽게 얽혀야 한다. RAAS의 '재상 안지오텐신 II'처럼 기능과 관계가 맞물리도록 한다. 로맨스/농담만 길어져 중심 기전이 사라지지 않게 한다.
B. 좀비 아포칼립스: 실제 좀비 위협과 생존·감염·방어·구조·탈출 등 장르 사건. 면역세포 등 학습 개념이 직접 행동해 위기에 기여한다. 고정된 구역 돌파 구조는 강제하지 않는다. 병원체와 좀비 비유의 한계를 주석에 명시한다.
C. 아이돌·연예계: 실제 K-pop 산업 분위기. 데뷔한 아이돌, 멤버·팬 교류, 공연, 컴백, 제작, 녹음실, 대기실, 숙소 일상 등 다양하게. 오디션→평가→데뷔 또는 공연 사고만 반복하지 않는다. 소소한 제작진 대화와 팬 반응만으로도 좋은 이야기 가능. 학습 개념의 실제 기능을 업무/신호/협업의 인과로 만든다.
D. 미스터리: 영국식/서양식 정통 탐정소설의 살인 사건, 탐정, 조수, 구분되는 용의자, 단서, 조사, 논리적 추리, 범인 공개. 개념이 단서·모순·알리바이 검증의 핵심이어야 한다. Concept-Driven Deduction: 단서→개념 적용→모순 발견→증거에 근거한 해결. 용의자 이름/역할을 명확히 구분하며, 가능하면 효소 경·기질 양처럼 개념명으로 의인화한다. 단순 의심이나 혈액형 일치만으로 살인을 단정하지 않는다. 비유적 '살인'과 실제 살인을 혼동하지 않는다.
E. 판타지 아카데미: 수업/교수 설명보다 기숙사, 야간 모험, 금지된 숲, 마법 파티, 신비한 동물, 비행, 친구 관계, 마법 도구와 사건 중심. 포도당·ATP·피루브산 등이 학생이나 등장인물이 되어 움직이는 자체가 매력 포인트. 학습 개념의 실제 변화와 기능이 마법의 원리가 된다. 특정 '기숙사 탈출→숲→용→귀환' 순서를 고정하지 않는다. 기존 유명 판타지 시리즈의 고유 인물·문구·설정은 복제하지 않는다.

3) Golden Example 사용법
- trytry_golden_examples.txt를 지식 자산으로 추가하되 장르별 예시의 '채택/후보', '원문 발췌/요약' 메타데이터를 유지한다.
- 예시의 문체와 작동 원리를 참조하되 이야기·대사·플롯을 매번 재사용하지 않는다.
- 로맨스판타지 1, 좀비 1, 아이돌 2, 미스터리 1 채택; 판타지 아카데미 1은 긍정 피드백이 있는 후보.
- 기존 지식 파일과 중복/충돌하면 기존 규칙을 무작정 누적하지 말고 하나의 정규화된 최신 규칙 소스로 통합하고 오래된 충돌 규칙을 제거한다. 파일 형식은 현재 저장소 관례에 맞춘다.

4) 엔지니어링 제약
- 기존 Next.js/TypeScript/Zod 구조 및 /api/analyze → /api/story 두 단계 흐름이 실제 존재하는지 확인하고, 존재한다면 유지한다.
- Storytelling 개선에 필요한 최소 범위만 수정한다. Melody Making, 인증, 저장, 배포, Firebase 설정, 사용자 데이터 흐름을 불필요하게 변경하지 않는다.
- 기존 UI 출력 계약(스토리, 주석, Flow Summary 등)을 보존하고 스키마를 깨지 않도록 한다.
- 긴 입력에서 지연/토큰 과다 문제를 악화시키지 않도록 예시 전체를 매 요청에 무조건 주입하지 말고 필요한 규칙/장르 예시를 선택적으로 활용한다.
- 안전성과 사실성: 원자료에 없는 의학적 사실을 단정하지 말고, 비유의 한계 및 주요 과학적 예외는 주석으로 명시한다. 실제 사료와 시대 설정을 임의로 사실인 것처럼 꾸미지 않는다.

5) 검증 및 산출물
- 5개 장르 각각의 테스트 케이스를 마련하고, 학습 개념의 기능 반영, 사건의 인과, 장르성, 과도한 설명, 캐릭터 명명, 사실성, 주석/Flow Summary 분리를 점검한다.
- 특히 효소 저해 미스터리(경쟁적 vs 순수 비경쟁적), 포도당→피루브산 2개, P/QRS/T, RAAS, 항원 인식의 핵심 장면을 회귀 점검한다.
- 가능하면 자동 테스트/타입체크를 실행하고 결과를 보고한다.
- 최종 응답에는 수정한 파일, 적용한 규칙, 테스트 결과, 남은 한계, 실제 배포 여부를 구분해 간결히 보고한다. 배포는 별도 지시가 없다면 수행하지 않는다.

먼저 현재 코드/규칙 파일을 살펴보고 충돌 사항을 파악한 다음, 필요한 변경을 구현해라. 불명확한 부분은 추측으로 기존 기능을 파괴하지 말 것.
